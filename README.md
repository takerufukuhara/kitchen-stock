# Kitchen Stock

飲食店の在庫管理、発注判断、廃棄分析、注文受付、仕込み管理をまとめて行うためのWebアプリです。  
飲食店で社員として働いた経験をもとに、「在庫数の確認」「発注漏れ」「廃棄の振り返り」「注文と在庫の連動」が手作業になりやすい課題を想定して作成しました。

## 作成背景

飲食店では、仕入れ、使用、廃棄、棚卸し、注文対応などの作業が日々発生します。これらを紙や口頭で管理すると、在庫の数え間違い、発注漏れ、廃棄理由の記録漏れが起きやすくなります。

このアプリでは、在庫の増減、注文、仕込み、廃棄を1つの画面で管理できるようにし、現場で必要な判断をしやすくすることを目的にしています。

## 主な機能

### 在庫管理

- 商品の追加、編集、削除
- 仕入れ、使用、廃棄、在庫修正の記録
- 複数商品のまとめて在庫操作
- カテゴリ別の在庫表示
- 在庫基準を下回った商品の強調表示

### 発注管理

- 在庫基準未満の商品を一覧表示
- 発注リストの自動生成
- 全体またはカテゴリ別の発注リストコピー

### 廃棄分析

- 廃棄した商品の記録
- 廃棄数や理由をもとに、在庫基準の見直しに活用

### メニュー管理

- メニューの登録、編集、削除
- メニューカテゴリの設定
- レシピとして使用する食材と使用量を登録
- 現在の在庫から作成可能数を表示
- 仕込み対象メニューの設定

### 仕込み管理

- 仕込みが必要なメニューだけを表示
- 仕込み数を入力すると、使用した食材を在庫から減算
- 仕込み対象メニューは、注文完了時に二重で在庫が減らないように制御

### 注文管理

- お客様用注文画面から注文を受け付け
- 注文予定リストからまとめて注文
- スタッフ側で受注、調理中、完成を管理
- 受注時間や注文内容をもとに、次に調理するメニューを判断しやすくする
- 調理開始時にレシピ分の在庫を自動減算
- 卓ごとの注文中リスト、注文履歴、キャンセル、スタッフ呼び出しを管理
- お客様側にも注文状態を表示

### 管理者ログイン

- 管理画面はログイン後に表示
- 在庫や注文の操作APIはバックエンド側で認証

## ローカルでの使い方

### 1. リポジトリを取得

```bash
git clone https://github.com/takerufukuhara/kitchen-stock.git
cd kitchen-stock
```

### 2. バックエンドを準備

```bash
cd backend
npm install
```

`backend/.env.example`を参考に、`backend/.env`を作成します。  
実際の`.env`ファイルには秘密情報が含まれるため、GitHubには公開しません。

バックエンドを起動します。

```bash
npm run dev
```

起動確認:

```text
http://localhost:3001/health
```

### 3. フロントエンドを準備

別のターミナルを開きます。

```bash
cd frontend
npm install
```

`frontend/.env.example`を参考に、`frontend/.env`を作成します。

フロントエンドを起動します。

```bash
npm run dev
```

ブラウザで開きます。

```text
http://localhost:5173
```

## 基本的な使い方

### お客様側

1. 卓の注文開始を行う
2. メニューを選ぶ
3. 数量を入力する
4. 注文予定リストに追加する
5. 注文する
6. 注文中リストで状態を確認する
7. 必要に応じてスタッフを呼ぶ
8. 会計後は注文できない状態になる

### スタッフ側

1. 管理画面にログインする
2. 注文管理で新しい注文を確認する
3. 調理を始める注文の「調理中」操作を行う
4. 調理開始時に、レシピに登録された食材が在庫から減る
5. 完成した注文を完了にする
6. キャンセルやスタッフ呼び出しを確認する

### 在庫管理

1. 商品を登録する
2. 単位、カテゴリ、在庫基準を設定する
3. 仕入れ、使用、廃棄、在庫修正を記録する
4. 在庫基準未満の商品を発注管理で確認する
5. 必要な発注リストをコピーする

### メニュー・仕込み管理

1. メニューを登録する
2. 使用する食材と使用量をレシピとして登録する
3. 仕込みが必要なメニューは「仕込み対象」にする
4. 仕込み管理で仕込み数を入力する
5. 仕込みに使った食材が在庫から減る

## 面接で説明しやすいポイント

- 飲食店勤務の経験から、現場で起きやすい在庫管理の課題をアプリ化したこと
- 単なる在庫一覧ではなく、注文、レシピ、仕込み、廃棄、発注までつなげて考えたこと
- 調理開始時に在庫を減らすなど、実務の流れに合わせて処理タイミングを設計したこと
- 仕込み対象メニューでは在庫が二重に減らないようにしたこと
- お客様画面と管理者画面を分け、管理操作はログイン後に行うようにしたこと
- 廃棄記録を在庫基準の見直しに活用できるようにしたこと

## 今後追加したい機能

実際の飲食店業務で使うことを想定し、注文、在庫、分析、管理の精度をさらに高める機能を追加していきたいと考えています。

- 調理優先度の提案
  - 受注時間、ファーストオーダー、同じメニューの重複注文などをもとに、スタッフが次に何を調理すればよいか判断しやすくするため
- 卓ごとの会計金額表示
  - 注文から会計までの流れをアプリ内で完結しやすくするため
- 注文履歴の検索、絞り込み
  - 過去の注文確認やトラブル対応をしやすくするため
- 商品ごとの在庫推移グラフ
  - 仕入れや使用量の傾向を見て、在庫基準を見直しやすくするため
- 廃棄傾向のグラフ化
  - どの商品が廃棄されやすいかを見える化し、仕入れ量の改善につなげるため
- スタッフごとの操作履歴
  - 誰がいつ在庫修正や注文操作を行ったか確認できるようにするため
- Supabase Authなどを使った本格的なユーザー管理
  - 複数スタッフで利用する場合に、権限管理やログイン管理をより安全にするため
